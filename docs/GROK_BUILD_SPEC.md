# MH伙伴助手公共 Web 应用开发执行文档

交付一个由 **Cursor Cloud Agent 构建、通过公共 HTTPS 地址访问的 Web 应用**。任何猎人都能在桌面或手机浏览器打开链接，免安装、免登录查《怪物猎人：世界》、Iceborne（冰原）与《怪物猎人：荒野》的资料、看活动、做配装。下载所选资料后可离线使用。会员登录后可以在不同浏览器之间同步个人数据。

## 1. 在 Cursor 云代理中启动

在 Cursor 中选择 **Cloud Agent** 和包含本文的仓库分支，把下面的指令交给代理。Grok Bot 也可以读取同一文件协调各任务。项目的构建和验收命令由仓库提供，不依赖特定模型的命令行语法。[Cursor Cloud Agents](https://cursor.com/docs/cloud-agent)

> 在这个仓库构建可运行、可发布为 Public 的 MH伙伴助手 Web 应用。读取 docs/GROK_BUILD_SPEC.md，从 T00 开始。并行安排资料 agent 抓取《MH伙伴：世界》和《MH伙伴：荒野》的 iOS、Android 公开资料，安排 UI agent 查看项目 images/ 中的风格参考图。把两端功能映射到 Web 操作和验收用例，把选用的视觉特征落实到主题和组件，并保留游民星空工具对照。先预览两作入口，再接通百科、地图、配装、日程与会员同步。用桌面和手机尺寸验证公开访问、离线刷新和私稿隔离。生成生产构建，按第 8、9 节验证公网地址。遇到缺失的参考图、正式资料或发布权限，记录具体缺口，继续独立任务。

**云端工作环境。** 协调员在云端检出中读取 README 和仓库指令，用 `git status --short --branch` 核对分支和工作树。以所选环境配置或仓库的 `.cursor/environment.json` 安装锁定依赖。在转发端口打开预览，记录本次构建的提交和入口。多代理在独立分支上工作时，从已交接的 T00 版本开始，由协调员集成。[Cursor 云环境设置](https://cursor.com/docs/cloud-agent/setup)

**架构选择。** 沿用原需求的 Flutter，构建目标为 **Flutter Web**。Go 服务从同一站点提供网页和 API，PostgreSQL 保存账户数据。浏览器用 IndexedDB 存结构化资料、私稿和同步队列，用 Cache Storage 存站点资源与离线地图。PC、PlayStation 和 Xbox 表示游戏数据适用的平台。没有实数时先用带 `fixture` 标记的小库跑通预览。

**公开访问约定。** 首页、百科详情、地图、活动、配装器及已发布方案允许匿名访问。公开页面不需要 Cursor 账户、团队邀请或访问密钥。访客可在当前浏览器保存收藏、库存和私稿。发布或撤回方案须验证本站用户身份，账户同步另校验会员权益。公开站点的可见性与每条配装的可见性分别管理。

**界面与导航。** 宽屏使用顶部导航，窄屏使用底部导航，均设置“首页、百科、配装、我的”。首页优先展示当前作品的限时任务和待更新资料。世界地图从首页及素材详情进入。“我的”集中收藏、装饰品、已存配装、会员空间、语言和通知设置。两作用不同的作品名、图标和点缀色。大字号下保留技能、时间、按钮全文，支持键盘焦点、返回/前进和触屏。分享优先调用浏览器分享功能，也可复制网址。给筛选、地图标记和配装操作提供可读标签，稀有度同时显示文字。

**第一次打开链接。** `/` 可选两作，`/g/:gameId/entries/:kind/:entryId` 直达百科，`/g/:gameId/events/:id` 直达活动，`/builds/:publicId` 打开公开快照。首次在线直达时按需加载该页资料，无需先下载完整离线包。刷新、复制链接、在无痕窗口粘贴都应落到同一条目。已撤回或不存在的公开记录显示相应状态。未公开的私稿只出现在其所有者的入口。

**全内容盘点。** 数据负责人为两作分别建立内容清单，按作品、扩展、游戏版本、平台、模块登记应有条目、已收录条目、关联、来源、缺项和负责人。以可合法查阅的旧版功能清单、官方游戏目录和人工核对资料对账，把“其他”条目逐项归类。拿到旧版样本后，盘点差异和迁移格式。界面完成、抽样准确、内容收齐分别验收。崛起与物语的专区仅作系列导航参考。本轮开发排期以表中的两作为准。

### 开发时使用用户提供的 UI 风格参考图

用户在网上收集的参考图片位于其 Mac 的 `/Users/kai/gat/my_git/MHBuddy/images`。开发时本机可直接读取该目录，Cursor 云代理优先从仓库根目录读取 `images/`，也可通过 `MH_UI_REFERENCE_DIR` 指向执行环境中实际挂载的目录。该路径仅供设计阶段读取。当前云端检出尚无这批图片，首次拿到图片的 agent 应重新盘点。

1. UI agent 枚举目录及子目录中的图片，打开原图再归纳。选有代表性的文件，在 `docs/execution/ui-style.md` 记下相对文件名、可观察的特征、要应用的组件。重点看主辅色及用色位置、标题与数值的字号层级、留白、卡片边界、导航和选中态。风格冲突时注明为哪个页面选了哪一项。来源、作品或平台不明的图片只作风格参考。
2. 在 Flutter Web 主题中定义采用的颜色、字体层级和间距，先将它们应用到首页入口、百科列表与详情、配装筛选与结果。窄屏优先保留操作顺序和可读性，宽屏可利用并栏呈现筛选和结果。公共网页使用项目自己的组件及可分发素材。网上收集的原图留在参考目录，构建时只打包明确列入发布清单的资源。
3. QA 在 390×844 和 1440×900 记录同一流程的 Web 截图，按“参考图文件名 → 选用特征 → Web 页面 → 观察结果”检查风格、字级和层次，并验证触控、键盘焦点和数据可读性。截图用于判断风格落实程度，无须像素级复刻。目录暂不可读时将图片对照标为“待提供”，先按既有主题完成页面与功能验收，图片可读后补做视觉复核。

## 3. 模块与数据流

仓库只有说明文件时建立下面的结构。路径为相对仓库根目录的目标位置。已有实现先在任务记录中映射对应路径。

| 主要路径 | 责任 |
| --- | --- |
| `apps/web/lib/shell/`、`apps/web/lib/l10n/` | Flutter Web 响应式导航、URL 路由、作品上下文、四语界面和无障碍。页面在 `apps/web/lib/features/`，浏览器入口与自有 Service Worker 在 `apps/web/web/` |
| `packages/catalog/` | 下载清单、按页加载、IndexedDB 内容和别名索引、激活版本、地图及百科查询接口 |
| `packages/builds/` | 纯 Dart 配装模型和按作品选择的求解器、荒野导入编解码。计算入口编译为浏览器专用 Web Worker |
| `packages/player_store/` | IndexedDB 个人库、访客与账户分区、收藏、库存、配装、事务队列和冲突处理 |
| `services/api/` | 单个 Go 服务提供 Web 构建产物与 API，处理日程、身份、会员与同步。PostgreSQL 保存身份、权益、公开快照与用户记录 |
| `tools/content/`、`content/` | 导入、编辑复核、建索引、打包、签名、审计。测试资料放 `content/fixtures/`，正式清单单独维护 |
| `contracts/`、`tests/acceptance/` | 版本化 JSON Schema、OpenAPI、错误码、跨端样例和端到端验收。契约在消费者实现前冻结首版 |
| `Makefile`、`docs/execution/` | 可重复的环境检查、启动和验收命令，任务状态、实际测试结果与数据覆盖报告 |

**读路径。** 编辑录入或导入 → 来源与版本复核 → 按作品、平台生成版本化 JSON 分片、索引和地图资源 → 发布清单。在线页面按条目索引请求所需分片，选择“下载离线资料”后在浏览器安装整包。日程有单独的更新通道。公开资源可经静态服务或 CDN 分发，开发环境使用相同格式。

**写路径。** 操作界面 → 在个人库事务内写入变更及待同步操作 → 界面立即读取本地结果 → 有网络和权益时推送 → 服务端事务校验并返回修订号 → 按游标拉取其他设备的变更。内容与个人数据使用独立 IndexedDB 数据库，更新资料包无需迁移用户库存。

## 4. 核心数据与接口契约

### 4.1 标识与存储

| 结构 | 必备字段和约束 |
| --- | --- |
| `GameContext` | `gameId` 为 `world` 或 `wilds`，另有 `contentProfile, platformId, patchId, dataRevision, rulesetVersion`。冰原是 `world` 的内容档。平台游戏版本与 Web 客户端版本分别记录 |
| `Entry / EntryText / Relation` | 稳定引用为 `(gameId, kind, entryId)`。数值、翻译、别名和有向关联各自建表。版本范围与平台差异随事实记录。缺少掉率等数值时保留未知。条目下架后保留稳定标识与替代关系 |
| `MapLayer / POI` | 底图、坐标系与版号绑定。点位保存 `mapId, layerId, xNorm, yNorm, area, kind, resourceRef, conditions, sourceRef`。原点左上，归一化坐标在 [0,1]，导入时校准。索引支持楼层、资源及稀有类型查询 |
| `Build / Inventory / Favorite` | 配装有用户记录 UUID、上下文、标题、装备及客制、逐孔装饰品、标签、创建/修改时间。库存按稳定装饰品引用存非负整数。收藏按用户分区与条目引用唯一。身份与内容包解耦 |
| `Event / Article` | 保留作品、平台、地区、来源、原文语言、译文审核状态与最后核实时间。任务另存原始时区、UTC 起止、常驻或待定状态、参与条件和奖励。赏金单列类别与刷新窗口。改期沿用稳定事件 ID |
| `SourceRecord / PackManifest` | 来源、权利范围与证据见第 6 节。清单含作品、内容档、平台、补丁、数据版、schema 版、规则版、最低客户端、大小、哈希、签名和资源列表。差分包另带父版本和基线哈希 |
| `Entitlement / Mutation` | 服务端管理 `planId, quotaBytes, usedBytes, expiresAt`。每次同步变更有 `opId, recordType, recordId, gameId, baseRevision, action, payload`。服务端按账户去重、分配修订号和游标 |

**语言与搜索。** 使用 `zh-Hans`、`zh-Hant`、`en`、`ja`。界面文案纳入四语资源检查。内容依次使用所选语言、包内默认译名、原文，并标出回退语言。为中日文建归一化名称、别名和子串索引，英文使用规范化词索引。支持大小写、全半角和日文假名的归一。短词走受限前缀或子串查询，分页稳定排序。在 Chromium、Firefox 和 WebKit 中核对 IndexedDB 索引查询、四语匹配和稳定分页。

### 4.2 服务边界

路径与请求体写入 `contracts/openapi.yaml`。结构化包与配装文件的完整校验规则写入 `contracts/schemas/`。下列路径均以 `/v1` 开头。

| 方法与路径 | 输入、响应与失败行为 |
| --- | --- |
| `GET /v1/packs/latest` | 查询作品、内容档、平台、游戏补丁和客户端版本。返回兼容清单、下载位置、变更摘要与 ETag。无兼容版本返回明确错误。未变化可返回 304 |
| `GET /v1/events`、`GET /v1/events/{id}`、`GET /v1/articles` | 匿名可读。列表按作品、平台、地区、语言、时间窗与游标筛选。活动详情由稳定 ID 读取，返回核实时间、改期或撤销状态，支持深链接及提醒重排 |
| `GET /v1/public-builds`、`GET /v1/public-builds/{id}`、`POST /v1/public-builds`、`DELETE /v1/public-builds/{id}` | 匿名可筛选大厅、读取已发布的单个快照。发布时鉴权、校验规则并只复制用户确认的公开字段。撤回须校验作者，撤回后公共查询不可再读。复制到个人库生成新 UUID，保留出处 |
| `POST /v1/auth/session`、`POST /v1/auth/refresh`、`DELETE /v1/auth/session` | 验证本站用户身份后建立同源会话，使用 Secure、HttpOnly、SameSite Cookie。刷新时轮换会话标识，退出时服务端撤销。测试身份提供器只在开发环境启用 |
| `POST /v1/reminders/subscriptions`、`DELETE /v1/reminders/subscriptions/{id}` | 对选择 Web Push 的浏览器登记订阅、事件与提醒时间。匿名订阅绑定浏览器专属撤销凭证，只有持有该凭证或相应账户的请求才能变更订阅 |
| `GET /v1/me/entitlement` | 返回有效权益、额度上限、实际用量和到期时间。客户端据此显示会员方案及升级/降级后的可用操作 |
| `POST /v1/sync/push` | 认证后按有界批次提交变更。每项独立事务并按 opId 返回 applied、conflict 或 rejected 及修订号/错误码。响应丢失后以同一 opId 重试 |
| `GET /v1/sync/pull`、`GET /v1/sync/snapshot` | 从账户游标返回有序变更、删除标记和下一游标。游标过期返回 `CURSOR_EXPIRED`。快照分页绑定同一水位，恢复后从该水位继续拉取 |

统一错误结构为 `{code, messageKey, requestId, details}`。失效认证返回 401。无权益为 403。不受支持的输入为 422。同步批次内的版本冲突与超额分别为 `REVISION_CONFLICT` 和 `QUOTA_EXCEEDED`。私有资源由服务端会话确定所有者，公开查询只返回已发布的字段。客户端识别可重试的网络/服务器错误，对永久错误显示具体操作。

## 5. 核心流程与实现要求

### 5.1 两作配装求解与编辑

1. 每作独立实现规则接口，至少包含装备合法性、孔位兼容、技能计算和汇总解释。规则随版本发布。复合装饰品、技能上限、套装效果、客制、武器切换等机制依照对应作品和补丁的核验样例启用。未知数值保留来源缺项。
2. `SolveRequest` 包含上下文、武器及客制选项、目标技能最低等级、固定与排除装备、自有装饰品开关及数量、排序、topK 和时间预算。固定与排除冲突先返回字段错误。启用库存时按每件珠子的实际消耗扣减。
3. 先按作品、进度、武器和固定条件缩小候选，再深度优先枚举各部位。仅在可证明达不到目标时按技能上界剪枝。分配兼容孔后按完整规则复算技能和套装效果。先用小库穷举作正确性基准，再优化。在专用 Web Worker 中求解，经消息通道回传进度和结果。用户可取消旧任务并发起新查询。
4. 荒野的求解输入可按装备实例预留指定类型和数量的插槽。分配珠子时保留这些孔，输出分别统计武器与防具的剩余孔。
5. `SolveResult` 返回每套的装备、逐孔分配、技能来源、有效等级、排序分值、规则与数据版，以及 `searchComplete` 和停止原因。只有完整搜索且无结果才显示“当前条件无解”。中断或超时显示已有结果与范围。默认按满足目标后剩余孔位、再按稳定 ID 排序，明确显示排序口径。结果页可按技能、防御、空孔再筛。全库重搜和当前结果筛选分别标明。
6. 已存配装支持重命名、修改、复制、标签和自动排序。默认按最近修改倒序，支持按名称和标签排序。相同值用记录 ID 稳定排序。旧配装在新数据包中打开时保留原引用与旧版信息，展示重算差异后再由用户保存。荒野保存和导入走荒野校验器。
7. 荒野的自动配装使用荒野规则计算目标技能、孔位和库存。配装大厅使用公开快照。用户可预览、复制到个人库、调整装备后单独发布或撤回。作者后续编辑私稿不改已发布快照，撤回后自己的本地副本仍可读取。

### 5.2 浏览器一键更新、离线与活动提醒

1. **首次打开。** 访客通过公开 HTTPS 地址直接选择作品、内容档、游戏平台及可选地图，查看离线大小后点击下载。Service Worker 预缓存本版 Flutter Web 应用外壳、静态路由回退页、渲染资源与字体。仅当应用外壳和所选数据均已就绪时显示“可离线使用”。首次访问需要联网。浏览器限制持久存储时保留在线浏览与搜索，提示具体受限功能。
2. **安装新版本。** 浏览器获取签名清单，用内置信任公钥验签并检查最低客户端、schema、规则版和容量。清单列出版本化 JSON 分片及地图底图、图标等资源的大小和 SHA-256。按分片下载、验哈希、校验 schema、数量和跨片引用，在 IndexedDB 按内容上下文及候选版本写入数据和搜索索引，在 Cache Storage 以不可变版本 URL 存放该版媒体。差分基线不符时请求完整包。账号数据、凭据和同步响应与公共离线缓存分开处理。
3. **激活与恢复。** 所有必需记录、索引和所选媒体可读后，在一个 IndexedDB 读写事务中比对旧版号并切换该上下文唯一的 `activeRevision`。同一页面读取时固定数据版本，地图与索引按相同版本解析。并发标签页更新时旧请求不得覆盖较新版本。下载中断、校验失败或配额不足时继续读取已激活版。重新打开后续传已校验的分片或回收暂存项。保留上一完整可用版，待读取结束再清理更老的版本。
4. **浏览器存储边界。** 支持时用 `navigator.storage.estimate()` 估算空间，写入仍须处理 `QuotaExceededError`。离线管理页显示各包大小、最后核实时间及删除入口。删除离线资料包只清理该包。浏览器“清除站点数据”、隐私模式或系统回收可能同时清除本机收藏和配装。启动时探测外壳、索引和资源完整性，提示重新联网修复及会员恢复已同步记录。验收时实测匿名下载后断网重开作品深链，检索装备、浏览已下载地图、编辑配装，再联网更新。
5. **活动提醒。** 日程保留来源时区、UTC 时间、地区、平台及最后核实时间，按设备时区显示。访客也能在站内订阅。支持 Web Push 时，在用户点击“启用推送”后请求权限，并以设备订阅、稳定事件 ID、平台及提醒类型去重。服务端按最新日程触发，改期重排、撤销清除待发任务，过期订阅清理。时间待定时保留关注状态。拒绝权限、不支持推送或订阅失效时，在打开网页及恢复前台时重新计算到期提醒，并提供含时区、稳定 UID 及版本 SEQUENCE 的日历事件下载。单次导入的日历需由用户在改期后刷新。网页关闭时的到点提醒取决于推送服务或日历客户端。断网打开缓存日程须显示最后核实时间。

### 5.3 会员与跨设备一致性

- 登录后先预览本机访客数据，用户选择是否合入该账户。保留来源 UUID 并幂等导入。每个账户独立数据库分区和队列，退出时撤销服务端会话并关闭当前分区，各标签页同步切回访客视图。新设备登录后从云端快照恢复已同步数据。
- 操作与 outbox 同事务落地。服务端在同一事务内完成幂等检查、baseRevision 检查、额度核算、写入和修订号分配。重复提交相同 opId 和内容应返回原结果，同一 opId 不同内容应拒绝。拉取一页的应用与游标推进也在同一本地事务内完成。
- 两端同时编辑同一配装时，保留两个版本供选择或合并。删除与修改竞争时保留删除标记和可恢复的冲突副本。库存提交绝对数量加基线修订，冲突展示两值供选择。收藏按条目标识去重。快照恢复期间保留未确认的本地操作，在新水位上重新校验。用户始终能区分“仅本地、同步中、已同步、待处理”。
- 会员方案由服务端配置额度、有效期和权益，空间按服务端规范化后的有效用户记录字节计算。升级即时生效。超额或降级时可读、可删、可做减少占用的修改，其余变更保留待同步。测试环境可配置两个额度档位验证边界。商业上线时由权利方提供方案与渠道信息，付费权益依据服务端验证的交易或既有会员系统授予。

## 6. 内容来源与发布质量

| 类型 | 使用方法 |
| --- | --- |
| Capcom 活动与补丁 | 作品、地区、平台和官方时间表优先核对。来源不提供适用平台时标注待确认。日程入口见[世界活动任务](https://game.capcom.com/world/cn/rank.html)和[荒野活动任务](https://info.monsterhunter.com/wilds/event-quest/ja/schedule)。 |
| 游民星空 | 用于发现攻略、装备分类、图鉴组织方式以及文章原链接。用户给出的工具链接对应荒野图鉴。参考[世界专区](https://www.gamersky.com/z/mhworld/)、[荒野专区](https://www.gamersky.com/z/monster-hunter-wild/)和[荒野图鉴](https://www.gamersky.com/tools/mhwiki/?ref=seo)。 |
| 作者与社区 | 将用户提供的 B站“MH伙伴”、微信公众号“MH伙伴”及微博作为候选关注入口，按可核验身份配置。翻译保留原作者、原文、语言和审核记录，分享默认使用原文或已获准发布的文章链接。[用户提供的微博](http://weibo.com/mhwo) |

1. 来源登记至少记录 `sourceId, urlOrEvidenceId, owner, allowedUse, attribution, observedAt, gameContext, reviewer`。区分引用链接、事实核对、摘录、翻译和离线再分发。优先采用自采可核对的结构化事实、自制地图/图标、授权数据和开放许可素材。可浏览的文章或图片只有在许可范围覆盖相应用途时才打包。
2. 接入器支持带来源字段的 CSV/JSON 和人工编辑。有可用且获准的机器来源再启用定时拉取。暂时不可达时收敛重试，使用上次核实记录，允许编辑手工修订。文章、图像、地图、数值及译文的版本均可回溯。更新先生成差异报告，复核后发布，可按包回滚。
3. 默认对允许轮询的活动源每 15 分钟检查一次。编辑批准后，联网前台客户端刷新并看到变更的目标为 15 分钟内。游戏补丁发现后 24 小时内登记受影响范围，已复核并获准分发的内容在 24 小时内进入可下载包。分别记录来源公布、发现、审核、发布和客户端可见的时间。来源故障和离线设备显示最后核实时间。
4. **准确度与完整度分开计算。** 每个游戏版本冻结一份独立核验的对照表，按平台、内容档和实体类型分层。默认每层用记录的随机种子抽 100 个应有字段值，不足 100 个全检。同一字段的跨平台差异依适用平台分别核对。分母为抽中的应有字段总数，正确且有证据的字段进入分子，缺失、错误、应有值未核实均计错。发布报告列出分子、分母、错项、分层结果和样本版本。门槛为世界含冰原 ≥98%、荒野 ≥99%，分别计算。关键时间、规则例和跨作引用单列全检。
5. 完整度以内容清单中应交付、已复核的条目数／该版应有条目数计量，并列出缺少的关联、素材和翻译。分母未知标“待盘点”。只有两作约定版本的所有适用类别、关联、地图层及必需译名全部对账、缺项清零，才标记“双作全量整合完成”。合成数据独立出包，只进入开发与测试渠道。

**实现与审查。** 导入和查询设大小上限，数据库查询参数化，资讯富文本限制元素和链接协议。Cookie 会话的写请求验证来源并防护 CSRF，私有读取和修改均按账户鉴权。个人数据响应带 `Cache-Control: private, no-store`，Service Worker 只缓存允许离线的公开资源。撤回可见性的公开配装详情也实时复核状态。密钥经服务端环境注入，前端只内置资料包验签公钥。列表批量加载，搜索取消旧请求，地图按视窗加载，检查热路径的查询计划、内存和离开页面后的订阅。

**具体 Diff 示例。** 在服务端 PostgreSQL 初始迁移 `services/api/migrations/001_player_records.sql` 中，单用账户与条目编号会让两作的同号收藏碰撞。浏览器 IndexedDB 和云端表应使用等价的复合唯一键。遇到既有库时写带备份、回填及重复检查的事务迁移，并保留待核实的历史数据。

```diff
-  UNIQUE (owner_id, entry_id)
+  UNIQUE (owner_id, game_id, kind, entry_id)
```

**派工和恢复。** 协调员在 `docs/execution/status.json` 单写状态。每项保存 `id, needs, owner, writes, status, attempt, revision, commands, evidence, blocker`。状态依次为 `pending → running → review → done`。审查未过回到 `pending`，确有外部依赖记 `blocked` 并写出恢复条件。只发放依赖均完成且写入范围互斥的任务。有 worktree 时隔离，无隔离条件时按路径串行写入。公共接口变化交由协调员统一改版，并重跑所有受影响消费者的检查。子 agent 不覆盖彼此的未提交修改。

每次启动先核对台账、工作树、产物与上次结果。中断的 `running` 项先查是否已经落盘并重跑对应验收，再决定续做或重试。若某项只缺特定浏览器、正式内容或发布权限，在 `evidence` 中逐条写明已验证部分与剩余前提，继续能够独立完成的工程检查。协调员负责集成，另一名审查者从干净检出复验。单执行器在独立检出中执行同一复验步骤。

**Cursor Apps 公开发布。** 代理使用生产构建准备 App，连接持久数据库、执行已验证的迁移，在预览中检查首页和深链接。应用所有者在发布托盘选择 **Publish** 和站点地址，平台检查通过后取得线上链接。在 Apps dashboard 的 **Access** 中确认 **Public**。Teams 或 Enterprise 若关闭公开分享，记录需要管理员启用的设置。协调员用全新浏览器会话、无 Cursor 登录和无访问令牌执行 A11，记录最终 HTTPS 地址、提交和时间。分别记录“预览可用”“已生成生产构建”“公网匿名访问已验证”。[Cursor Apps 发布与共享](https://cursor.com/docs/cloud-agent/apps)
