## 1. 公开页上的不足和由此看到的痛点

| 公开页里能分开的事实 | 猎人会碰到的事 |
| --- | --- |
| 《MH伙伴：世界／冰原》和《MH伙伴：荒野》是两个 App。内购结构不同：世界版中国区页有多档会员和永久契约，荒野版中国区页是 VIP 和打赏 | 两作都玩的人要装两套、记两套会员。网页若只做其中一作，换作品就得换工具 |
| 两边的配装说明都是在选技能、固定或排除装备、用「我的装饰品」或护石当条件。世界版 2.16.2 仍在修「选了技能，回到配装器不立刻刷新」和觉醒技能不同步 | 猎人要自己把「打这只怪、偏输出还是偏生存」翻译成技能等级。条件一旦没刷上，算出来的套装是旧的 |
| 世界版简介写分级云存储，但没写每档容量。同一档位在页面上出现两次，看不出是列重了还是两种周期 | 付钱之前不知道空间够不够 |
| 游民星空能打开的是荒野图鉴和荒野配装器。配装说明写了自动配装和手动大厅。抽查的世界／冰原工具路径当天是 404。2019 年攻略把世界配装指到站外工具 | 只玩世界／冰原的人，在游民这边没有对等的自有工具。玩荒野的人可以逛大厅，但大厅和「我有哪些珠」不是同一套账号说明 |
| 游民图鉴有招式动作值。两款 MH伙伴 的当天公开说明里没有同名入口。图鉴首页脚本没有地图、机械武器、猫饭、极限突破这些入口；荒野版更新记录里有后几项 | 想查动作帧的人留在游民。想查世界地图、或做荒野机械武器和猫饭的人留在对应 App。没有一个地方把「这套装备为什么适合这只怪」和「缺的素材去哪刷」接在一起 |
| 游民工具页没有版本号。2025-07 攻略横幅写过「海龙版本」，不能当成 2026-11-23 仍是最新。两款 App 的 98%、99% 是简介口径，不是公开的审计表 | 猎人分不清套装是哪一版，也不知道数字有没有被复核 |
| 荒野应用宝停在 1.13.0，iOS 是 1.14.6，页上没有这段差距的更新说明 | 安卓用户可能看不到 iOS 更新记录里的功能。具体少了什么，待复核 |

这些痛点里，本方案优先处理三件：用一句话描述狩猎目标而不是先填技能表；每套结果都说明理由并且数字只能来自求解器；缺什么素材就回到百科里已核对的掉落，而不是让模型编一只怪。

## 2. 和三家工具的差异

差异只谈猎人能感知的操作。不谈「我们更准确」，因为正式资料还没有审计。

| 猎人想做的事 | 世界／冰原 App | 荒野 App | 游民星空工具 | 本方案 |
| --- | --- | --- | --- | --- |
| 说「用这把武器打这只怪，我偏会心，珠和护石是这些」 | 公开说明是技能和装备条件，不是这种句子 | 公开说明是保存、修改、导入；版本记录是技能、孔位、护石、极限突破等条件 | 配装器说明是自动配装、大厅、武器类型和孔数 | 增加这种句子。句子只负责变成求解条件，套装仍由现有算分引擎产出 |
| 看懂为什么是这套 | 结果按条件筛选，公开页没写对着怪物解释 | 配装卡展示武器技能等图标，公开页没写对着怪物解释 | 大厅可以抄一套，说明页没写逐条理由 | 每套附带理由：技能从哪件装备来、对应怪物的哪条已核对弱点、还缺哪颗珠 |
| 看缺的素材去打谁 | 地图和百科是分开的入口 | 百科有掉落类条目；公开页没写「从缺料反推怪物」 | 图鉴能查怪物和素材，配装器说明没写这条回路 | 缺料清单只链接百科里已有的掉落关系。没有关系就写「还没核对」，不补一只怪 |
| 两作放在一起 | 只覆盖世界／冰原 | 只覆盖荒野 | 当天打开的自有工具是荒野 | 继续一个站点两作。世界和荒野的规则、珠子、怪物不能混在一次求解里 |
| 不登录先试 | App 可离线查已更新的库；云存储要会员 | 类似，中国区页是 VIP 与打赏 | 工具页没看到会员存储 | 表单配装和百科保持访客可用。模型调用单独计次，见额度 |

不把下面几项写成这轮差异：招式动作值、机械武器模拟、猫饭、极限突破、社区大厅里的别人的套装数量。前几项要么只有一边的公开入口，要么我们没有可分发的数据。大厅「300 多种」是 2025-03-11 的文章数字，不当成现在的规模。

## 3. 重点：AI 辅助配装

### 3.1 用户场景

四个场景都从配装页进入，标题用「用一句话配装」。旁边保留现在的条件配装。模型次数用完、或所有者尚未开通模型时，条件配装仍然可用。

**场景 A：说出目标和家当，得到一套并看到理由。**

猎人输入或点选这些块，也可以只打一句话，由界面拆开：

- 作品：世界／冰原，或荒野。冰原是世界的内容档，不是第三部作品。
- 武器：类型或具体名字。
- 目标怪物：名字。
- 玩法风格：输出、会心、生存、辅助这一类短词。可多选，也可不选。
- 已有素材、装饰品、护石：名字和数量。不填表示「先假设珠子够用」，结果里要标明这个假设。

主按钮是「生成配装」。生成中可以停止。完成后先看到 1 套，可以再看下几套。每套包含：

- 武器、五部位、逐孔装饰品、护石（这作有护石时）。
- 三段理由，都带到来源：哪条技能达到了哪一级、来自哪件装备或哪颗珠；怪物的哪条弱点或肉质被用到，以及该字段的资料版本；还缺什么、缺的话这套就不成立。
- 一句资料状态：夹具、或已复核的某个资料版本。夹具套装不能写成「实战可用」。

猎人可以改一句再生成，例如「不要这件头」。上一套留在页面上，直到新的一套算完，避免闪回空白。

**场景 B：对着现有配装给优化建议。**

入口在「我的配装」和已打开的公开配装上，按钮是「看看还能怎么改」。猎人补一件事：还想加强什么（继续打同一只怪、换成生存、或「我新做了一颗珠」）。

建议以「改动」的形式出现，而不是另一篇攻略：换下哪一件、换上哪一件、技能等级因此升了还是降了、空孔是多了还是少了。没有更优解时直说「按现在的珠和目标，没有更好的一套」，并给出已经比较过的范围（搜完了，还是时间到了停止）。

公开配装上的建议先落在猎人自己的副本里。不改别人已经发布的快照。

**场景 C：缺什么，就去打谁。**

从场景 A 或 B 的「还缺」列表出发。每一行缺的素材或珠子显示：

- 百科里已经写明的掉落怪物、任务或采集点。世界素材若有核对过的地图点，给「地图查看」。
- 若这条素材没有掉落关系，写「这条还没有核对过的获取方式」，不出现怪物名。

不要求猎人再开一次模型。这一步是查表。

**场景 D：说不清楚时先追问，不直接出套装。**

名字对上多条、作品没说、武器和怪物不属于同一作、风格和「不要某技能」互相打架时，先给选项让猎人点。不猜一个最像的然后出装。

### 3.2 交互原则

- 一句话和条件表写的是同一份求解请求。猎人展开「它听成了什么」时，能看到武器、怪物、风格、库存、排除装备，并能改其中一项再算。避免世界版 2.16.2 那种「条件改了，结果还是旧的」：每次生成都用刚确认的那份请求，旧计算作废。
- 理由里的数字、技能名、装备名都可以点进百科。点不进去的名字不准出现。
- 风格是给猎人看的词。内部要落到一份由人维护的技能优先级表（例如「会心」对应哪些技能、先堆到几级）。这张表随资料版本走，不由模型当场发明。
- 世界和荒野分两次算。预留武器孔只属于荒野。觉醒、极限突破、机械武器只有在该版本的规则样例已经进求解器时才能当条件；否则告诉猎人「这版规则还不能算这一项」，而不是用相近系统顶上。
- 访客能看自己这次的结果。会员才能把对话和结果存进账户。退出后，服务器不再把这台浏览器当成那个账户。

### 3.3 技术方案

计算分四步。只有第一步和可选的润色会用到模型。套装和缺料不用模型编。

1. **听懂。** 模型只输出一份固定结构：作品、内容档、武器候选、怪物候选、风格词、已有珠和护石的原文片段、排除词、是否假设珠子无限。不允许它输出攻击力、技能等级或装备 id。
2. **对上资料。** 用百科的名称和别名索引把候选收成条目 id。零条就追问或拒绝。多条就请猎人点选。这一步在浏览器里对已加载的资料做，不把整包百科发给模型。
3. **求解。** 把对上的 id 收成现有求解器已经接受的请求：目标技能、固定武器、排除装备、库存数量、荒野预留孔、时间上限。技能目标来自「怪物已核对字段 + 风格优先级表」，不来自模型。求解器返回装备、逐孔珠、技能来源、空孔、是否搜完。库存不足就无解，和现在的夹具规则一样，不能为了有结果而偷偷假设猎人有珠。
4. **写给人看。** 默认用模板把求解器的技能来源、百科弱点和缺料关系填成三段话，不调用模型。若所有者开通了润色，模型只能重写这段模板的语序，并且必须原样保留模板里的条目 id 和数字。服务端再核对：理由中的每个数字和 id 都能在求解结果或百科字段里找到，否则丢掉润色，退回模板。

缺料反推不经过模型。素材到怪物、任务、采集点，只走百科里已有的关联。关联缺失就显示缺失。

和现有引擎的关系：继续用按作品分开的合法性、孔位和技能汇总。模型不替换求解器，也不能在求解器返回空时「推荐一套常见配装」。空结果就是空结果。

夹具阶段可以做界面和假请求的走查，但按钮若打到模型，结果页第一句必须是「夹具，不是游戏实数」。更稳妥的做法是：正式资料包启用前，不把模型按钮暴露给访客。这一点交给所有者定，见第 5 节。

### 3.4 模型选型与成本

这里不指定厂商，也不写一份会过期的价目。密钥和合同都还没有。

建议拆成两个可以分开买的调用，避免每次配装都走大模型：

| 调用 | 做什么 | 输入输出量级 | 能否关掉 |
| --- | --- | --- | --- |
| 听懂 | 把一句话收成上面的固定结构 | 短。输入是猎人的句子和少量候选名字，输出是一小段结构 | 不能关掉，否则没有「一句话」入口。可以改成完全手填，那就不需要这个调用 |
| 润色 | 只改模板的说法 | 输入是已经填好的模板，输出是同一信息的另一种说法 | 默认可关。关掉就只用模板，费用为零 |

听懂适合用便宜、支持结构化输出的小模型。润色若要开，也用小模型，不用长上下文的大模型把整本百科读进去。整本资料留在本地求解和查表。

成本按「成功的一次听懂」记，不按猎人打了多少字预估成一口价。同一次确认过的请求重复求解，只重跑求解器，不再扣听懂次数。追问、对不上名字、润色被核对丢掉，都不算一次成功配装。

月成本大致是：成功听懂次数 × 每次听懂的 token × 供应商单价，加上润色次数 × 润色 token × 单价。单价以合同为准。上线前设一个硬顶：到顶后听懂接口拒绝，条件配装和模板理由继续可用。硬顶的金额见第 5 节。

不在浏览器里放模型密钥。调用只走本站服务端。没有密钥时，服务端不提供听懂接口，页面不显示「生成配装」。

### 3.5 怎样避免幻觉

- 模型看不见攻击、会心、孔位、掉落这些字段，也就不能改它们。这些字段只从资料包和求解结果来。
- 名字先对上条目 id。对不上就停。
- 理由里的数字和 id 必须能在结果或百科里找到，否则整段润色作废。
- 资料包里标了未知或未核对的值，理由里写「还没有这个数」，不用相近怪物填。
- 夹具、过期资料版本、规则样例未覆盖的系统（机械武器、猫饭、极限突破、觉醒，在对应规则未接入前）都明确说不能算。
- 不生成「社区都在用」「强度第一」这类没有来源的句子。
- 求解中断时展示已有结果，并写明没搜完。只有搜完且为空才写无解。

### 3.6 访客与会员额度

额度说的是模型调用，不是百科和条件配装。后两者维持现在的约定：访客可用，不登录。

| | 访客 | 会员 |
| --- | --- | --- |
| 条件配装、百科、世界地图、活动、看公开配装 | 可用，不计模型次数 | 可用 |
| 一句话听懂 | 每台浏览器每天很少的几次，用完即停 | 同一账户更高的每日次数，并受全站月硬顶约束 |
| 润色 | 默认关。若所有者对访客也开，计入同一次听懂，不另计 | 可随会员方案打开，仍受核对失败就退回模板的约束 |
| 结果留存 | 只在这台浏览器，清站点数据就没了 | 存在该账户下，可同步。不进入别人的公开配装 |
| 优化建议、缺料反查 | 只要这次结果还在本地，就可用。反查不计模型次数 | 同左，并且可以以后再打开 |
| 次数用尽 | 说明今天的生成次数用完，条件配装仍在 | 说明额度用尽或全站本月已停。不自动扣费 |

具体「很少的几次」和会员次数不在这里定死。第 5 节给了一组建议数，等所有者改。

会员仍不是商店里的那几档价格。本站没有支付。开发环境里的字节额度是同步空间，和模型次数不是同一个账本，不要混在一个数字里。

没有登录时，用浏览器里的随机额度凭证计次，和活动提醒的匿名撤销凭证同一类做法：清站点数据会换一张新凭证，也会丢掉本机剩余次数的记录。不为此去对身份证或手机号。

### 3.7 隐私

- 发给模型的内容只限于：猎人这句话、为消歧而附上的少量候选名字（名字和条目 id）、以及待润色的模板。不发送整包百科、其他猎人的配装、会话 Cookie、同步队列。
- 库存只上传猎人这次点名的珠、护石和数量。不上传账户里没被这句话用到的收藏和配装。
- 默认不把提示词用于训练，也不向猎人展示「你的配装将帮助改进模型」。若供应商合同做不到这一点，就不开通该供应商。
- 服务端若记日志，成功对上 id 之后只留请求 id、作品、条目 id 和是否搜完，便于算账和排错。猎人的原句默认不落库。排错需要原句时，单独开关、单独期限，见第 5 节。
- 访客数据不进账户库。会员的生成记录按账户隔离，另一个账户的同步快照读不到。
- 公开配装页上的「看看还能怎么改」使用猎人自己补上的目标和库存。不会把这套建议写回那条公开快照。
- 界面在发送前用一句话写明：这句话会送到本站的配装服务，用来收成求解条件。不写供应商名字，直到所有者选定。

## 4. 其他面向用户的优化

工作量不用工期表示。小：只动已有页面的展示或把现有结果填进模板。中：新的页面状态，仍用现有求解器或百科关联。大：新的在线服务、额度账本，或必须先有正式资料。

优先级：P0 是一句话配装若要可信就绕不开的；P1 直接减轻第 1 节里的痛；P2 有用，但排在前面两项之后，或还缺资料。

## 5. 待所有者决定

下面每一项都会碰到 API 密钥、付费，或对外承诺。未决定前，方案停在本文，不接服务，也不在界面上显示已开通。

1. **模型供应商和密钥放在哪。** 需要一支只放在服务端的密钥，以及是否接受该供应商的地区和数据处理条款。不接受「提示词可能被用于训练」的，换供应商或只做模板、不做听懂。
2. **听懂和润色各选哪一档模型。** 建议听懂用小模型，润色默认为关。所有者选定具体型号和单价后，才能把第 3.4 节的月成本算成金额。
3. **全站每月硬顶。** 到顶后关闭听懂，条件配装和模板理由继续服务。建议先设一个小硬顶做试运行，金额由所有者填。
4. **访客和会员的每日次数。** 建议试运行：访客每台浏览器每天 3 次成功听懂；会员每天 30 次。这只是建议，不是已生效规则。也可以决定访客完全不调用模型，只让会员使用一句话。
5. **是否在夹具资料上对访客开放模型按钮。** 建议不开。夹具数字一旦被说成配装建议，就和「避免幻觉」冲突。试运行可以限制在已登录的内部账户。
6. **原句要不要为了排错保存、保存多久。** 建议默认不保存。若打开，建议不超过 7 天，并且和条目 id 日志分开。
7. **会员是否收费、和哪一档模型次数绑定。** 本站没有价格和支付渠道。在渠道确定前，会员次数只存在于试运行账户，不写进公开售价。
8. **正式资料谁提供、能否再分发。** 没有这份授权，一句话配装只能停在夹具演示。这和模型密钥是两件独立的事。

## 6. 待复核

- 两款 App 或游民工具的界面里，是否已有未写进商店简介和工具说明的「自然语言配装」或「按怪物出装」。2026-11-23 核对到的公开页没有这种描述。
- 世界版 2.16.2 之前的配装条件全量清单。觉醒之外还有哪些冰原系统，公开页没有列全。
- 荒野安卓 1.13.0 相对 iOS 1.14.6 少了哪些功能。
- 游民图鉴和配装器当天是否仍停在 2025-07 所说的海龙版本。
- 招式动作值要不要做。游民有入口，MH伙伴公开记录未见同名项。没有可分发的动作数据之前不排进上表。
- 拼音之外的注音、日文、韩文是否纳入搜索。商店简介和语言列表并不一致。
- 世界版会员每档容量、重复出现的内购是一次还是两种周期。本方案不引用那些价格。
